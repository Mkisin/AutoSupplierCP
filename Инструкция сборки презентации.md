# Инструкция сборки презентации КП

Этот файл — рабочий промпт-инструкция для Codex/ассистента, чтобы каждый раз собирать презентацию КП одинаково и не восстанавливать процесс по памяти.

## Цель

Собрать индивидуальную презентацию КП для одной компании из базы проекта на основе шаблона `Шаблон ЦЗС.pptx`.

Итоговый файл должен быть PPTX с подставленными текстовыми блоками, статистикой по товарной категории, отзывом и изображениями.

## Основные входные файлы

- `Данные для разработки.xlsx`
  - лист `Карточка клиента`: карточки компаний и параметры КП.
  - лист `Статистика по группам`: статистика переговоров по категориям.
- `Отзывы.xlsx`
  - источник компании, ФИО и текста отзыва для блоков `{{block6}}`, `{{block7}}`, `{{block8}}`.
- `Шаблон ЦЗС.pptx`
  - основной шаблон презентации.
- `Шаблоны для вставки.md`
  - карта placeholder-переменных.
- `pic1 qr platforma czs.jpg`
  - изображение для `{{pic1}}`, если имя содержит `pic1`.
- `Фотки переговоров/`
  - фотографии для `{{pic2}}`, `{{pic3}}`, `{{pic4}}`.
- `Логотипы поставщиков/`
  - логотип поставщика для `{{logo1}}`.

Важно: в старых скриптах может встречаться папка `Фотки`, но в текущем проекте фактическая папка называется `Фотки переговоров`. Перед сборкой проверить и при необходимости поправить скрипт или создать корректную ссылку на папку.

## Основные скрипты

- `build_payload.py`
  - читает Excel и формирует JSON payload с заменами.
  - принимает название компании аргументом командной строки.
- `build_presentation_direct.py`
  - собирает PPTX напрямую через ZIP/XML, без запуска PowerPoint.
  - вызывает `build_payload.py`.
- `build_gosudarev_presentation.ps1`
  - запасной вариант через PowerPoint COM.
  - использовать только если прямой Python-вариант не подходит.

## Как выбрать компанию

1. Открыть/прочитать `Данные для разработки.xlsx`, лист `Карточка клиента`.
2. Найти строку по точному названию компании.
3. Если у компании несколько строк с разными контактами, выбрать контакт по приоритету:
   - коммерческий директор / коммерческий отдел;
   - генеральный директор;
   - директор;
   - любой другой контакт.
4. Не выдумывать данные, которых нет в карточке.

## Обязательные поля карточки

Перед сборкой проверить, что для выбранной компании заполнены:

- `Название компании`
- `ИНН`
- `Тип компании`
- `ФИО контакта`
- `Должность контакта`
- `Отрасль`
- `Сфера деятельности`
- `Категория по работе с сетями`
- `Сайт`
- `Страна`
- `Город`
- `Название товара`
- `Категория товара`
- `Ценовая категория`

Если обязательных полей не хватает, сначала попросить пользователя дозаполнить или дозаполнить через форму параметров.

## Placeholder-карта

Использовать соответствия из `Шаблоны для вставки.md`:

- `{{block1}}`: `Как компании [Название компании] получить 5-10 контрактов с розничными сетями за 2 дня, проведя 30-40 переговоров`
- `{{block2}}`: категория продукции из поля `Категория товара`
- `{{block3}}`: колонка `Переговоров` листа `Статистика по группам`
- `{{block4}}`: колонка `Интерес` листа `Статистика по группам`
- `{{block5}}`: колонка `Чемпионы` листа `Статистика по группам`
- `{{pic1}}`: картинка из корня проекта, имя содержит `pic1`
- `{{pic2}}`, `{{pic3}}`, `{{pic4}}`: фотографии из `Фотки переговоров/`
- `{{logo1}}`: логотип из `Логотипы поставщиков/`
- `{{block6}}`: название компании из `Отзывы.xlsx`
- `{{block7}}`: ФИО представителя из `Отзывы.xlsx`
- `{{block8}}`: текст отзыва из `Отзывы.xlsx`

## Как выбирать статистику

1. Взять `Категория товара` из карточки клиента.
2. Найти ближайшую строку на листе `Статистика по группам`.
3. Сначала искать точное/частичное совпадение по названию группы.
4. Если точного совпадения нет, искать по пересечению значимых слов.
5. Для мясных категорий можно маппить на `Мясные деликатесы`.
6. Если совпадение не найдено, использовать средние значения по листу как временный benchmark и явно указать в выводе `stats_source=average_food_benchmark`.

## Как выбирать отзыв

Для MVP допустимо брать первый валидный отзыв из `Отзывы.xlsx`, но лучше:

1. Искать отзыв из похожей категории товара.
2. Если похожего нет, брать универсальный положительный отзыв.
3. Не менять смысл отзыва.
4. Не генерировать отзыв от имени реальной компании без источника.

## Команда сборки

Основной вариант:

```powershell
python -X utf8 build_presentation_direct.py "Название компании"
```

Пример:

```powershell
python -X utf8 build_presentation_direct.py "ООО \"БиоФудЛаб\""
```

Проверка без создания PPTX:

```powershell
python -X utf8 build_presentation_direct.py --dry-run "Название компании"
```

Если кавычки в названии мешают PowerShell, использовать точное название без организационных кавычек только после проверки, что скрипт найдет компанию. Лучше при необходимости доработать поиск в `build_payload.py`, а не переименовывать данные в Excel.

## Название итогового файла

Скрипт формирует имя:

`[slug компании]_ЦЗС_переменные.pptx`

Если файл уже существует, должен создаваться вариант:

`[slug компании]_ЦЗС_переменные_v2.pptx`, `v3` и так далее.

## Проверка результата

После сборки обязательно проверить:

- файл PPTX создан;
- в выводе есть `text_replaced` больше 0;
- в выводе есть `image_replaced` больше 0, если в шаблоне есть image placeholders;
- `client`, `contact`, `position`, `category` соответствуют выбранной компании;
- в итоговом файле не осталось видимых placeholder-токенов `{{block...}}`, `{{pic...}}`, `{{logo...}}`;
- статистика соответствует категории или явно помечена как benchmark;
- изображения не пустые и не сломали структуру слайдов.

## Что не делать

- Не редактировать исходный `Шаблон ЦЗС.pptx` при сборке.
- Не выдумывать реальные ФИО и должности.
- Не затирать Excel или презентации пользователя.
- Не использовать случайные изображения из интернета без согласования.
- Не менять `Данные для разработки.xlsx`, если задача только собрать презентацию.

## Что уже улучшено в скриптах

- `build_presentation_direct.py` использует папку `Фотки переговоров`.
- Логотип поставщика подбирается по названию компании, названию товара и категории, а не берется первым файлом из папки.
- Если поле `Фото товара` заполнено и файл существует, оно используется для `{{pic2}}`; остальные фото берутся из `Фотки переговоров`.
- Отзыв подбирается по пересечению значимых слов с категорией товара. Если совпадений нет, берется первый валидный отзыв.
- После сборки выводится отчет: сколько раз заменен каждый text placeholder, какие картинки вставлены, какие источники картинок не найдены, какие placeholder остались в презентации.
- Есть режим `--dry-run`, который показывает payload, плановые картинки и будущий файл без создания PPTX.
