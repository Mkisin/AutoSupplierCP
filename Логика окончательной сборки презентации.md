# Логика окончательной сборки презентаций.docx

Сервис делает так:

1. **PPTX собирается первым**

   Ручной запуск идет из фронта через `POST /api/presentations`:
   [backend/app.py](c:/Users/Менеджер_004/Documents/Корпоративная%20школа/Обучение%20AI/AutoSupplierCP/backend/app.py:2534).

   Backend проверяет:
   - есть `companyName`;
   - есть одобренный выбор материалов `approvedSelectionId`;
   - выбор относится к этой компании.

   Потом создает `job_id` и в отдельном потоке запускает
   `_run_presentation_job(..., make_pdf=True)`.

2. **Генератор PPTX**

   `_run_presentation_job` вызывает отдельный Python-скрипт:

   ```python
   build_presentation_direct_new.py <company>
   ```

   См.
   [backend/app.py](c:/Users/Менеджер_004/Documents/Корпоративная%20школа/Обучение%20AI/AutoSupplierCP/backend/app.py:620).

   Внутри
   [build_presentation_direct_new.py](c:/Users/Менеджер_004/Documents/Корпоративная%20школа/Обучение%20AI/AutoSupplierCP/build_presentation_direct_new.py:1368):
   - читает payload через `build_payload_new.py`;
   - берет шаблон `Шаблон презентации новый.pptx`;
   - формирует имя результата вида `<company>_ЦЗС_новый.pptx`;
   - заменяет текстовые плейсхолдеры `{{block...}}`;
   - заменяет картинные плейсхолдеры `{{pic...}}`, `{{logo...}}`;
   - нормализует изображения в PNG перед вставкой;
   - пишет новый PPTX как zip-пакет, напрямую меняя XML слайдов и
     `.rels`.

   То есть `python-pptx` тут не используется, PPTX правится на уровне
   OpenXML.

3. **Данные для PPTX**

   Payload строит
   [build_payload_new.py](c:/Users/Менеджер_004/Documents/Корпоративная%20школа/Обучение%20AI/AutoSupplierCP/build_payload_new.py:1):
   - читает Excel `Данные для разработки.xlsx`;
   - находит компанию;
   - подбирает статистику, отзывы, фото, логотипы;
   - собирает `replacements` для `{{block1}}`, `{{block2}}` и т.д.

   Одобренный выбор ИИ/пользователя передается в генератор через
   env-переменную `PRESENTATION_SELECTION_JSON`, и уже в
   `apply_selection_override` переопределяет фото, отзывы и логотипы.

4. **PDF делается из готового PPTX**

   После успешной сборки backend берет путь `created` из JSON-отчета
   генератора и вызывает `_convert_pptx_to_pdf(created)`:
   [backend/app.py](c:/Users/Менеджер_004/Documents/Корпоративная%20школа/Обучение%20AI/AutoSupplierCP/backend/app.py:421).

   Порядок конвертации:
   - если задан `ILOVEPDF_PUBLIC_KEY`, пробует iLovePDF API;
   - иначе ищет `PPTX_TO_PDF_CONVERTER`, `soffice` или
     `libreoffice`;
   - если это Windows и LibreOffice нет, пробует Microsoft PowerPoint
     через COM;
   - если COM через Python не сработал, пробует PowerShell COM-скрипт;
   - если ничего нет, ошибка: нужен LibreOffice/soffice или PowerPoint.

5. **Скачивание**

   Готовые `.pptx` и `.pdf` отдаются одним эндпоинтом:

   [backend/app.py](c:/Users/Менеджер_004/Documents/Короративная%20школа/Обучение%20AI/AutoSupplierCP/backend/app.py:2572)

   ```text
   GET /api/presentations/{filename}
   ```

   Он разрешает только `.pptx` и `.pdf`.

6. **Bitrix-ветка**

   В Bitrix pipeline сервис делает то же самое, но синхронно и с
   `require_pdf=True`:
   [backend/app.py](c:/Users/Менеджер_004/Documents/Корпоративная%20школа/Обучение%20AI/AutoSupplierCP/backend/app.py:2927).

   Поэтому для Bitrix PDF обязателен. После конвертации PDF загружается в
   поле `presentationFileField` через `_bitrix_upload_file`.
